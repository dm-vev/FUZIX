# Документ требований: Порт FuzixOS для ESP32-S3

## Введение

Данный документ описывает требования к полному порту операционной системы FuzixOS для микроконтроллера ESP32-S3 с поддержкой WiFi и внешней PSRAM. ESP32-S3 представляет собой современный 32-битный микроконтроллер с двухъядерным процессором Xtensa LX7, встроенным WiFi, Bluetooth LE и возможностью подключения внешней PSRAM до 32 МБ.

## Глоссарий

- **ESP32-S3**: Микроконтроллер семейства ESP32 от Espressif Systems с двухъядерным процессором Xtensa LX7
- **PSRAM**: Pseudo Static RAM - внешняя оперативная память, подключаемая через SPI/QSPI интерфейс
- **WiFi_Stack**: Программный стек для работы с беспроводной сетью WiFi
- **MMU**: Memory Management Unit - блок управления памятью
- **FuzixOS**: Unix-подобная операционная система для встраиваемых систем
- **Xtensa_LX7**: Архитектура процессора от Cadence/Tensilica
- **SPI_Flash**: Внешняя флеш-память, подключенная через SPI интерфейс
- **UART**: Universal Asynchronous Receiver-Transmitter - последовательный интерфейс
- **GPIO**: General Purpose Input/Output - порты ввода-вывода общего назначения
- **Swap_Device**: Устройство для организации виртуальной памяти
- **Root_Filesystem**: Корневая файловая система
- **Kernel_Image**: Образ ядра операционной системы
- **Bootloader**: Загрузчик операционной системы
- **IDF**: IoT Development Framework от Espressif
- **SDK**: Software Development Kit - набор средств разработки

## Требования

### Требование 1: Базовая поддержка процессора ESP32-S3

**Пользовательская история:** Как разработчик системы, я хочу иметь базовую поддержку процессора ESP32-S3, чтобы ядро FuzixOS могло загружаться и выполняться на этом оборудовании.

#### Критерии приемки

1. THE Kernel_Image SHALL загружаться на ESP32-S3 через стандартный Bootloader от Espressif
2. THE Kernel_Image SHALL инициализировать оба ядра процессора Xtensa LX7
3. THE Kernel_Image SHALL настраивать тактовую частоту процессора на 240 МГц
4. THE Kernel_Image SHALL инициализировать MMU для управления памятью
5. WHEN Kernel_Image загружается, THE System SHALL выводить диагностические сообщения через UART0
6. THE Kernel_Image SHALL поддерживать обработку прерываний от аппаратных таймеров
7. THE Kernel_Image SHALL реализовывать переключение контекста между процессами

### Требование 2: Поддержка внешней PSRAM

**Пользовательская история:** Как разработчик системы, я хочу использовать внешнюю PSRAM, чтобы увеличить доступную оперативную память для процессов пользователя.

#### Критерии приемки

1. THE System SHALL обнаруживать наличие внешней PSRAM при загрузке
2. WHEN PSRAM обнаружена, THE System SHALL инициализировать её через QSPI интерфейс
3. THE System SHALL поддерживать PSRAM размером до 32 МБ
4. THE System SHALL настраивать MMU для отображения PSRAM в адресное пространство
5. THE System SHALL использовать PSRAM для размещения пользовательских процессов
6. THE System SHALL корректно обрабатывать отсутствие PSRAM и работать только с внутренней SRAM
7. WHEN процесс выделяет память, THE System SHALL предпочтительно использовать PSRAM для данных пользователя

### Требование 3: Поддержка WiFi

**Пользовательская история:** Как пользователь системы, я хочу иметь возможность подключаться к WiFi сетям, чтобы использовать сетевые приложения и сервисы.

#### Критерии приемки

1. THE System SHALL инициализировать WiFi_Stack при загрузке
2. THE System SHALL предоставлять интерфейс для сканирования доступных WiFi сетей
3. WHEN пользователь указывает SSID и пароль, THE System SHALL подключаться к WiFi сети
4. THE System SHALL поддерживать WiFi в режимах Station (клиент) и Access Point (точка доступа)
5. THE System SHALL реализовывать стек TCP/IP для работы через WiFi
6. WHEN WiFi соединение установлено, THE System SHALL создавать сетевой интерфейс wlan0
7. THE System SHALL поддерживать автоматическое переподключение при потере связи
8. THE System SHALL предоставлять утилиты для управления WiFi соединением

### Требование 4: Управление памятью

**Пользовательская история:** Как разработчик системы, я хочу эффективно управлять доступной памятью, чтобы максимизировать количество одновременно работающих процессов.

#### Критерии приемки

1. THE System SHALL разделять память на области для ядра и пользовательских процессов
2. THE System SHALL использовать внутреннюю SRAM (512 КБ) для критичных данных ядра
3. WHEN PSRAM доступна, THE System SHALL размещать пользовательские процессы в PSRAM
4. THE System SHALL реализовывать механизм подкачки (swap) на SPI_Flash или SD карту
5. THE System SHALL поддерживать динамическое выделение памяти для процессов
6. WHEN память заканчивается, THE System SHALL использовать Swap_Device для выгрузки неактивных процессов
7. THE System SHALL предотвращать фрагментацию памяти через механизм банков памяти

### Требование 5: Файловая система и хранилище

**Пользовательская история:** Как пользователь системы, я хочу иметь постоянное хранилище для файлов и программ, чтобы сохранять данные между перезагрузками.

#### Критерии приемки

1. THE System SHALL поддерживать Root_Filesystem на внутренней SPI_Flash
2. THE System SHALL резервировать область флеш-памяти для Bootloader и Kernel_Image
3. THE System SHALL поддерживать подключение SD карты через SPI интерфейс
4. WHEN SD карта подключена, THE System SHALL монтировать её как /dev/hdb
5. THE System SHALL поддерживать файловую систему FuzixFS на флеш-памяти
6. THE System SHALL поддерживать создание разделов подкачки на SD карте
7. THE System SHALL реализовывать wear leveling для продления срока службы флеш-памяти

### Требование 6: Последовательные интерфейсы и консоль

**Пользовательская история:** Как пользователь системы, я хочу взаимодействовать с системой через последовательный порт, чтобы выполнять команды и получать вывод программ.

#### Критерии приемки

1. THE System SHALL инициализировать UART0 как консольное устройство /dev/tty1
2. THE System SHALL настраивать UART0 на скорость 115200 бод
3. THE System SHALL поддерживать ввод и вывод через UART0
4. THE System SHALL реализовывать буферизацию для последовательного порта
5. WHEN пользователь вводит команды, THE System SHALL обрабатывать их через shell
6. THE System SHALL поддерживать дополнительные UART интерфейсы (UART1, UART2)
7. THE System SHALL предоставлять устройства /dev/ttyN для дополнительных UART

### Требование 7: Сетевой стек TCP/IP

**Пользовательская история:** Как разработчик приложений, я хочу использовать стандартные сетевые сокеты, чтобы создавать сетевые приложения.

#### Критерии приемки

1. THE System SHALL реализовывать стек TCP/IP поверх WiFi интерфейса
2. THE System SHALL поддерживать сокеты BSD для TCP и UDP
3. THE System SHALL реализовывать DHCP клиент для автоматического получения IP адреса
4. THE System SHALL поддерживать статическую конфигурацию IP адреса
5. WHEN сетевое соединение активно, THE System SHALL поддерживать DNS резолвинг
6. THE System SHALL реализовывать базовые сетевые утилиты (ping, ifconfig, netstat)
7. THE System SHALL поддерживать множественные одновременные сетевые соединения

### Требование 8: Драйверы периферии

**Пользовательская история:** Как разработчик приложений, я хочу иметь доступ к периферийным устройствам ESP32-S3, чтобы создавать приложения для работы с оборудованием.

#### Критерии приемки

1. THE System SHALL предоставлять драйвер для GPIO портов
2. THE System SHALL поддерживать SPI интерфейс для подключения внешних устройств
3. THE System SHALL поддерживать I2C интерфейс для подключения датчиков
4. THE System SHALL предоставлять доступ к аппаратным таймерам
5. THE System SHALL поддерживать PWM для управления яркостью и моторами
6. THE System SHALL предоставлять драйвер для встроенного RTC (часы реального времени)
7. THE System SHALL поддерживать watchdog таймер для повышения надёжности

### Требование 9: Процессы и многозадачность

**Пользовательская история:** Как пользователь системы, я хочу запускать несколько программ одновременно, чтобы эффективно использовать ресурсы системы.

#### Критерии приемки

1. THE System SHALL поддерживать вытесняющую многозадачность
2. THE System SHALL реализовывать планировщик процессов с приоритетами
3. THE System SHALL поддерживать до 32 одновременных процессов
4. WHEN PSRAM доступна, THE System SHALL размещать несколько процессов в памяти одновременно
5. WHEN PSRAM недоступна, THE System SHALL использовать режим swap-only
6. THE System SHALL поддерживать fork() и exec() для создания процессов
7. THE System SHALL реализовывать межпроцессное взаимодействие через pipes и signals

### Требование 10: Совместимость с существующими портами

**Пользовательская история:** Как разработчик системы, я хочу максимально использовать существующий код FuzixOS, чтобы упростить разработку и поддержку порта.

#### Критерии приемки

1. THE System SHALL использовать существующую архитектуру cpu-esp32 как основу
2. THE System SHALL следовать соглашениям именования и структуре каталогов FuzixOS
3. THE System SHALL использовать существующие драйверы устройств где это возможно
4. THE System SHALL поддерживать стандартный формат исполняемых файлов FuzixOS
5. THE System SHALL быть совместимым с существующими утилитами и приложениями FuzixOS
6. THE System SHALL использовать стандартные системные вызовы FuzixOS
7. THE System SHALL документировать все отличия от базовой реализации ESP32

### Требование 11: Инструменты сборки и развёртывания

**Пользовательская история:** Как разработчик системы, я хочу иметь удобные инструменты для сборки и прошивки системы, чтобы упростить процесс разработки.

#### Критерии приемки

1. THE System SHALL предоставлять Makefile для сборки ядра
2. THE System SHALL поддерживать сборку с использованием xtensa-esp32s3-elf toolchain
3. THE System SHALL генерировать образы для прошивки через esptool
4. THE System SHALL предоставлять скрипты для автоматической прошивки устройства
5. THE System SHALL поддерживать создание образа файловой системы
6. THE System SHALL документировать процесс сборки и установки
7. THE System SHALL предоставлять примеры конфигурации для различных плат ESP32-S3

### Требование 12: Энергосбережение

**Пользовательская история:** Как пользователь системы, я хочу иметь возможность управлять энергопотреблением, чтобы продлить время работы от батареи.

#### Критерии приемки

1. THE System SHALL поддерживать режим light sleep для снижения энергопотребления
2. THE System SHALL автоматически переводить WiFi в режим энергосбережения при неактивности
3. THE System SHALL поддерживать динамическое изменение частоты процессора
4. THE System SHALL предоставлять API для управления режимами энергосбережения
5. WHEN система неактивна, THE System SHALL снижать тактовую частоту процессора
6. THE System SHALL поддерживать пробуждение от внешних прерываний
7. THE System SHALL предоставлять утилиты для мониторинга энергопотребления

### Требование 13: Отладка и диагностика

**Пользовательская история:** Как разработчик системы, я хочу иметь инструменты для отладки и диагностики, чтобы быстро находить и исправлять проблемы.

#### Критерии приемки

1. THE System SHALL выводить отладочные сообщения через UART0 при загрузке
2. THE System SHALL поддерживать различные уровни детализации логирования
3. THE System SHALL предоставлять информацию о состоянии памяти через /proc/meminfo
4. THE System SHALL поддерживать дамп регистров процессора при критических ошибках
5. THE System SHALL логировать события WiFi подключения и отключения
6. THE System SHALL предоставлять утилиты для мониторинга системных ресурсов
7. THE System SHALL поддерживать JTAG отладку через OpenOCD

### Требование 14: Безопасность и надёжность

**Пользовательская история:** Как пользователь системы, я хочу, чтобы система была надёжной и защищённой, чтобы предотвратить потерю данных и несанкционированный доступ.

#### Критерии приемки

1. THE System SHALL проверять целостность Kernel_Image при загрузке
2. THE System SHALL корректно обрабатывать исключения процессора
3. THE System SHALL предотвращать доступ пользовательских процессов к памяти ядра
4. THE System SHALL реализовывать watchdog для автоматической перезагрузки при зависании
5. WHEN происходит критическая ошибка, THE System SHALL сохранять дамп памяти
6. THE System SHALL поддерживать базовую систему прав доступа к файлам
7. THE System SHALL защищать WiFi пароли от несанкционированного чтения

### Требование 15: Производительность

**Пользовательская история:** Как пользователь системы, я хочу, чтобы система работала быстро и эффективно, чтобы приложения выполнялись с приемлемой скоростью.

#### Критерии приемки

1. THE System SHALL загружаться за время не более 5 секунд
2. THE System SHALL обеспечивать переключение контекста за время не более 100 микросекунд
3. THE System SHALL поддерживать пропускную способность WiFi не менее 10 Мбит/с
4. THE System SHALL обеспечивать скорость чтения/записи на SD карту не менее 1 МБ/с
5. WHEN используется PSRAM, THE System SHALL минимизировать задержки доступа к памяти
6. THE System SHALL оптимизировать использование кэша процессора
7. THE System SHALL поддерживать не менее 200 переключений контекста в секунду
