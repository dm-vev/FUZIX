# Документ проектирования: Порт FuzixOS для ESP32-S3

## Обзор

Данный документ описывает архитектурное проектирование полного порта операционной системы FuzixOS для микроконтроллера ESP32-S3 с поддержкой WiFi и внешней PSRAM. Проект основывается на существующем порте для ESP32, но включает значительные улучшения для поддержки новых возможностей ESP32-S3.

### Ключевые отличия ESP32-S3 от ESP32

- **Процессор**: Xtensa LX7 (вместо LX6) с улучшенной производительностью
- **Память**: До 512 КБ внутренней SRAM + до 32 МБ внешней PSRAM
- **WiFi**: Улучшенный WiFi 802.11b/g/n с поддержкой WPA3
- **Периферия**: Больше GPIO (45 вместо 34), улучшенные SPI/I2C интерфейсы
- **USB**: Встроенный USB OTG (отсутствует в ESP32)
- **Безопасность**: Улучшенные функции безопасности и шифрования

### Карта памяти ESP32-S3

ESP32-S3 использует архитектуру с раздельными адресными пространствами для инструкций и данных:

**Пространство данных:**
```
0x3C000000 - 0x3C7FFFFF  8MB      Внешняя PSRAM (через кэш)
0x3FC88000 - 0x3FCFFFFF  480KB    Внутренняя SRAM1
0x3FF00000 - 0x3FF7FFFF  512KB    Периферия и регистры
0x3FF80000 - 0x3FF87FFF  32KB     Внутренняя SRAM0
```

**Пространство инструкций:**
```
0x40000000 - 0x4001FFFF  128KB    Внутренний ROM
0x40370000 - 0x403DFFFF  448KB    Внутренняя SRAM1 (для кода)
0x42000000 - 0x427FFFFF  8MB      Внешняя флеш (через кэш)
0x3C000000 - 0x3C7FFFFF  8MB      Внешняя PSRAM (для кода)
```

## Компоненты и интерфейсы

### 1. Модуль инициализации процессора (cpu-esp32s3)

**Назначение:** Инициализация процессора Xtensa LX7, настройка MMU, обработка прерываний.

**Основные файлы:**
- `Kernel/cpu-esp32s3/cpu.h` - определения для архитектуры LX7
- `Kernel/cpu-esp32s3/lowlevel-esp32s3.S` - низкоуровневые функции на ассемблере
- `Kernel/cpu-esp32s3/types.h` - типы данных для 32-битной архитектуры

**Интерфейсы:**
```c
// Инициализация процессора
void cpu_init(void);

// Настройка MMU для отображения памяти
void mmu_setup(void);

// Переключение контекста процесса
void switch_context(struct p_tab *old, struct p_tab *new);

// Обработка прерываний
void interrupt_handler(uint32_t cause);
```

### 2. Модуль управления памятью (memory manager)

**Назначение:** Управление внутренней SRAM и внешней PSRAM, выделение памяти процессам.

**Основные файлы:**
- `Kernel/platform/platform-esp32s3/memory.c` - управление памятью
- `Kernel/platform/platform-esp32s3/psram.c` - драйвер PSRAM

**Интерфейсы:**
```c
// Инициализация PSRAM
bool psram_init(void);

// Получение размера доступной PSRAM
size_t psram_get_size(void);

// Выделение памяти из PSRAM для процесса
void *psram_alloc(size_t size);

// Освобождение памяти PSRAM
void psram_free(void *ptr);

// Проверка доступности PSRAM
bool psram_available(void);
```

### 3. Модуль WiFi (wifi driver)

**Назначение:** Управление WiFi интерфейсом, подключение к сетям, реализация сетевого стека.

**Основные файлы:**
- `Kernel/platform/platform-esp32s3/devwifi.c` - драйвер WiFi
- `Kernel/platform/platform-esp32s3/wifi_config.c` - конфигурация WiFi

**Интерфейсы:**
```c
// Инициализация WiFi
int wifi_init(void);

// Сканирование доступных сетей
int wifi_scan(struct wifi_ap_record *aps, uint16_t *count);

// Подключение к сети
int wifi_connect(const char *ssid, const char *password);

// Отключение от сети
int wifi_disconnect(void);

// Получение статуса подключения
int wifi_get_status(struct wifi_status *status);

// Настройка режима AP
int wifi_start_ap(const char *ssid, const char *password);
```

### 4. Модуль файловой системы (filesystem)

**Назначение:** Работа с файловой системой на SPI Flash и SD карте.

**Основные файлы:**
- `Kernel/platform/platform-esp32s3/devflash.c` - драйвер SPI Flash
- `Kernel/platform/platform-esp32s3/devsdspi.c` - драйвер SD карты

**Интерфейсы:**
```c
// Инициализация флеш-памяти
int flash_init(void);

// Чтение блока из флеш
int flash_read_block(uint32_t block, void *buffer);

// Запись блока во флеш
int flash_write_block(uint32_t block, const void *buffer);

// Стирание блока флеш
int flash_erase_block(uint32_t block);

// Инициализация SD карты
int sd_init(void);

// Чтение/запись блоков SD карты
int sd_read_block(uint32_t block, void *buffer);
int sd_write_block(uint32_t block, const void *buffer);
```

### 5. Модуль последовательных портов (serial driver)

**Назначение:** Управление UART интерфейсами для консоли и отладки.

**Основные файлы:**
- `Kernel/platform/platform-esp32s3/devtty.c` - драйвер UART

**Интерфейсы:**
```c
// Инициализация UART
void uart_init(uint8_t uart_num, uint32_t baud_rate);

// Отправка байта через UART
void uart_putc(uint8_t uart_num, char c);

// Получение байта из UART
int uart_getc(uint8_t uart_num);

// Проверка наличия данных в буфере
bool uart_data_available(uint8_t uart_num);
```

### 6. Модуль подкачки (swapper)

**Назначение:** Управление виртуальной памятью, подкачка процессов на диск.

**Основные файлы:**
- `Kernel/platform/platform-esp32s3/swapper.c` - реализация подкачки

**Интерфейсы:**
```c
// Инициализация системы подкачки
void swap_init(void);

// Выгрузка процесса на диск
int swap_out(struct p_tab *process);

// Загрузка процесса с диска
int swap_in(struct p_tab *process);

// Получение свободного места для подкачки
uint32_t swap_free_space(void);
```

### 7. Модуль сетевого стека (network stack)

**Назначение:** Реализация TCP/IP стека поверх WiFi.

**Основные файлы:**
- `Kernel/platform/platform-esp32s3/network.c` - сетевой стек
- `Kernel/platform/platform-esp32s3/tcp.c` - реализация TCP
- `Kernel/platform/platform-esp32s3/udp.c` - реализация UDP

**Интерфейсы:**
```c
// Инициализация сетевого стека
int network_init(void);

// Создание сокета
int socket_create(int domain, int type, int protocol);

// Привязка сокета к адресу
int socket_bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen);

// Подключение сокета
int socket_connect(int sockfd, const struct sockaddr *addr, socklen_t addrlen);

// Отправка данных
ssize_t socket_send(int sockfd, const void *buf, size_t len, int flags);

// Получение данных
ssize_t socket_recv(int sockfd, void *buf, size_t len, int flags);
```

## Модели данных

### Структура процесса (расширенная для ESP32-S3)

```c
struct esp32s3_process_data {
    // Базовая информация процесса (из FuzixOS)
    struct p_tab base;
    
    // Специфичные для ESP32-S3 данные
    uint32_t psram_base;        // Базовый адрес в PSRAM
    uint32_t psram_size;        // Размер выделенной PSRAM
    uint32_t code_base;         // Адрес кода в памяти
    uint32_t code_size;         // Размер кода
    uint32_t data_base;         // Адрес данных в памяти
    uint32_t data_size;         // Размер данных
    uint32_t stack_base;        // Адрес стека
    uint32_t stack_size;        // Размер стека
    
    // Контекст процессора Xtensa LX7
    uint32_t pc;                // Program Counter
    uint32_t ps;                // Processor Status
    uint32_t sar;               // Shift Amount Register
    uint32_t ar[64];            // Address Registers (windowed)
    
    // Флаги состояния
    uint8_t in_psram;           // Процесс размещён в PSRAM
    uint8_t swapped_out;        // Процесс выгружен на диск
};
```

## Свойства корректности

*Свойство - это характеристика или поведение, которое должно выполняться во всех допустимых выполнениях системы - по сути, формальное утверждение о том, что система должна делать. Свойства служат мостом между спецификациями, понятными человеку, и гарантиями корректности, проверяемыми машиной.*


### Свойство 1: Корректность переключения контекста процессов

*Для любых* двух процессов P1 и P2, когда происходит переключение контекста от P1 к P2, состояние регистров P1 должно быть сохранено, а состояние регистров P2 должно быть восстановлено, и при обратном переключении от P2 к P1 состояние P1 должно быть идентично сохранённому.

**Валидирует: Требования 1.7, 9.1**

### Свойство 2: Размещение процессов в PSRAM

*Для любого* пользовательского процесса, если PSRAM доступна и имеет достаточно свободного места, процесс должен быть размещён в PSRAM, а не во внутренней SRAM.

**Валидирует: Требования 2.5, 2.7, 4.3, 9.4**

### Свойство 3: Подключение к WiFi сети

*Для любых* валидных SSID и пароля существующей WiFi сети, вызов функции подключения должен успешно установить соединение и создать сетевой интерфейс wlan0.

**Валидирует: Требования 3.3, 3.6**

### Свойство 4: Автоматическое переподключение WiFi

*Для любого* установленного WiFi соединения, если соединение потеряно по причине, не зависящей от пользователя (потеря сигнала, перезагрузка точки доступа), система должна автоматически попытаться переподключиться в течение 30 секунд.

**Валидирует: Требования 3.7**

### Свойство 5: Динамическое выделение памяти

*Для любого* запроса на выделение памяти размером N байт, если доступно не менее N байт свободной памяти (PSRAM или SRAM), система должна успешно выделить память и вернуть валидный указатель, а при освобождении этой памяти она должна стать доступной для последующих выделений.

**Валидирует: Требования 4.5**

### Свойство 6: Подкачка при нехватке памяти

*Для любого* состояния системы, когда свободная память падает ниже порогового значения (например, 64 КБ), система должна выгрузить наименее активный процесс на Swap_Device, освободив память для других процессов.

**Валидирует: Требования 4.6**

### Свойство 7: Предотвращение фрагментации памяти

*Для любой* последовательности операций выделения и освобождения памяти, после N операций (где N > 1000), размер наибольшего непрерывного блока свободной памяти должен составлять не менее 50% от общего объёма свободной памяти.

**Валидирует: Требования 4.7**

### Свойство 8: Монтирование SD карты

*Для любой* корректно отформатированной SD карты, подключенной к SPI интерфейсу, система должна обнаружить карту при загрузке или при вызове команды монтирования и сделать её доступной как /dev/hdb.

**Валидирует: Требования 5.4**

### Свойство 9: Wear leveling для флеш-памяти

*Для любой* последовательности операций записи на флеш-память, после N операций записи (где N > 10000), стандартное отклонение количества записей по всем блокам флеш-памяти не должно превышать 20% от среднего значения.

**Валидирует: Требования 5.7**

### Свойство 10: Корректность передачи данных через UART

*Для любых* данных размером до 4096 байт, отправленных через UART0, данные должны быть корректно переданы на принимающую сторону без потерь и искажений (при условии отсутствия аппаратных ошибок).

**Валидирует: Требования 6.3**

### Свойство 11: Обработка команд shell

*Для любой* валидной команды shell из стандартного набора FuzixOS (ls, cd, cat, echo, и т.д.), shell должен корректно разобрать команду, выполнить её и вернуть соответствующий код возврата.

**Валидирует: Требования 6.5**

### Свойство 12: DNS резолвинг

*Для любого* валидного доменного имени (например, example.com), при активном сетевом соединении, система должна успешно разрешить имя в IP адрес через DNS запрос.

**Валидирует: Требования 7.5**

### Свойство 13: Множественные сетевые соединения

*Для любого* количества одновременных TCP соединений до 16, система должна корректно поддерживать все соединения, обеспечивая независимую передачу данных для каждого соединения.

**Валидирует: Требования 7.7**

### Свойство 14: Вытесняющая многозадачность

*Для любых* двух или более процессов с одинаковым приоритетом, каждый процесс должен получать процессорное время пропорционально количеству процессов, с отклонением не более 10% от равномерного распределения за период в 1 секунду.

**Валидирует: Требования 9.1**

### Свойство 15: Планировщик с приоритетами

*Для любых* двух процессов P1 и P2, где приоритет P1 выше приоритета P2, процесс P1 должен получать процессорное время чаще, чем P2, в соотношении не менее 2:1 за период в 1 секунду.

**Валидирует: Требования 9.2**

### Свойство 16: Корректность fork() и exec()

*Для любого* процесса, вызов fork() должен создать идентичную копию процесса с новым PID, а последующий вызов exec() в дочернем процессе должен заменить его образ на новую программу, сохраняя открытые файловые дескрипторы (если не установлен флаг close-on-exec).

**Валидирует: Требования 9.6**

### Свойство 17: Межпроцессное взаимодействие через pipes

*Для любых* двух процессов, соединённых через pipe, данные, записанные одним процессом в pipe, должны быть доступны для чтения другим процессом в том же порядке (FIFO), без потерь и дублирования.

**Валидирует: Требования 9.7**

### Свойство 18: Совместимость исполняемых файлов

*Для любого* исполняемого файла в стандартном формате FuzixOS, система должна корректно загрузить файл, разместить его в памяти и начать выполнение, если файл не повреждён и соответствует архитектуре.

**Валидирует: Требования 10.4**

### Свойство 19: Совместимость приложений

*Для любого* стандартного приложения FuzixOS (например, утилиты из пакета coreutils), приложение должно работать на ESP32-S3 порте без модификаций и с тем же поведением, что и на других платформах FuzixOS.

**Валидирует: Требования 10.5**

### Свойство 20: Совместимость системных вызовов

*Для любого* системного вызова из стандартного набора FuzixOS, вызов должен иметь ту же сигнатуру, семантику и возвращаемые значения, что и в базовой реализации FuzixOS.

**Валидирует: Требования 10.6**

### Свойство 21: Автоматическое управление энергопотреблением WiFi

*Для любого* WiFi соединения, если в течение 60 секунд не происходит передачи данных, WiFi модуль должен автоматически перейти в режим энергосбережения, снижая энергопотребление не менее чем на 50%.

**Валидирует: Требования 12.2**

### Свойство 22: Динамическое управление частотой процессора

*Для любого* периода неактивности системы длительностью более 5 секунд (отсутствие активных процессов, ожидающих выполнения), система должна автоматически снизить тактовую частоту процессора до 80 МГц или ниже.

**Валидирует: Требования 12.5**

### Свойство 23: Обработка исключений процессора

*Для любого* исключения процессора (деление на ноль, недопустимый доступ к памяти, недопустимая инструкция), система должна корректно обработать исключение, завершить процесс-нарушитель и продолжить работу других процессов.

**Валидирует: Требования 14.2**

### Свойство 24: Защита памяти ядра

*Для любого* пользовательского процесса, попытка чтения или записи в область памяти ядра (адреса 0x3FF80000 и выше для SRAM) должна быть заблокирована MMU и привести к исключению доступа к памяти.

**Валидирует: Требования 14.3**

### Свойство 25: Сохранение дампа при критической ошибке

*Для любой* критической ошибки ядра (kernel panic), система должна сохранить дамп памяти ядра и регистров процессора в зарезервированную область флеш-памяти перед перезагрузкой.

**Валидирует: Требования 14.5**

### Свойство 26: Система прав доступа к файлам

*Для любого* файла с установленными правами доступа (например, только для чтения), попытка записи в файл процессом без соответствующих прав должна быть отклонена с ошибкой EACCES.

**Валидирует: Требования 14.6**

### Свойство 27: Защита WiFi паролей

*Для любого* пользовательского процесса без привилегий root, попытка чтения файла конфигурации WiFi, содержащего пароли, должна быть отклонена с ошибкой EACCES.

**Валидирует: Требования 14.7**


## Обработка ошибок

### Стратегия обработки ошибок

Система использует многоуровневый подход к обработке ошибок:

1. **Аппаратные ошибки**: Обрабатываются на уровне драйверов с попытками восстановления
2. **Ошибки ядра**: Приводят к kernel panic с сохранением дампа памяти
3. **Ошибки процессов**: Завершают процесс-нарушитель, не затрагивая систему
4. **Сетевые ошибки**: Обрабатываются с автоматическими повторными попытками

### Категории ошибок

#### 1. Ошибки инициализации

**Ошибка**: Не удалось инициализировать PSRAM
- **Обработка**: Система продолжает работу с внутренней SRAM, выводит предупреждение
- **Восстановление**: Автоматическое, система работает в ограниченном режиме

**Ошибка**: Не удалось инициализировать WiFi
- **Обработка**: WiFi функции недоступны, система продолжает работу
- **Восстановление**: Пользователь может попытаться переинициализировать WiFi

**Ошибка**: Повреждена корневая файловая система
- **Обработка**: Kernel panic, система не загружается
- **Восстановление**: Требуется перепрошивка файловой системы

#### 2. Ошибки выполнения

**Ошибка**: Нехватка памяти для выделения
- **Обработка**: Попытка подкачки процессов, если не помогает - возврат NULL
- **Восстановление**: Автоматическое при освобождении памяти

**Ошибка**: Потеря WiFi соединения
- **Обработка**: Автоматические попытки переподключения (до 5 попыток)
- **Восстановление**: Автоматическое при восстановлении сигнала

**Ошибка**: Исключение процессора в пользовательском процессе
- **Обработка**: Завершение процесса с сигналом SIGSEGV
- **Восстановление**: Не требуется, система продолжает работу

#### 3. Критические ошибки

**Ошибка**: Исключение процессора в ядре
- **Обработка**: Kernel panic, сохранение дампа, перезагрузка
- **Восстановление**: Автоматическая перезагрузка через watchdog

**Ошибка**: Повреждение структур данных ядра
- **Обработка**: Kernel panic, сохранение дампа, перезагрузка
- **Восстановление**: Автоматическая перезагрузка через watchdog

**Ошибка**: Переполнение стека ядра
- **Обработка**: Kernel panic, сохранение дампа, перезагрузка
- **Восстановление**: Автоматическая перезагрузка через watchdog

### Коды ошибок

Система использует стандартные коды ошибок POSIX:

- `ENOMEM` (12): Недостаточно памяти
- `EACCES` (13): Отказано в доступе
- `ENODEV` (19): Устройство не найдено
- `EINVAL` (22): Недопустимый аргумент
- `ENOSPC` (28): Нет места на устройстве
- `ENETDOWN` (100): Сеть недоступна
- `ECONNREFUSED` (111): Соединение отклонено

### Логирование ошибок

Все ошибки логируются через UART0 с указанием:
- Временной метки
- Уровня серьёзности (DEBUG, INFO, WARNING, ERROR, CRITICAL)
- Компонента, в котором произошла ошибка
- Описания ошибки
- Контекста (PID процесса, адрес памяти, и т.д.)

Пример:
```
[12345.678] ERROR [memory] Failed to allocate 65536 bytes for process 5
[12345.679] WARNING [swapper] Attempting to swap out process 3
[12345.680] INFO [swapper] Successfully swapped out process 3, freed 32768 bytes
```

## Стратегия тестирования

### Двойной подход к тестированию

Система использует комбинацию unit-тестов и property-based тестов для обеспечения корректности:

**Unit-тесты**:
- Проверяют конкретные примеры и граничные случаи
- Тестируют интеграцию между компонентами
- Проверяют обработку ошибок

**Property-based тесты**:
- Проверяют универсальные свойства на множестве входных данных
- Обеспечивают широкое покрытие через рандомизацию
- Находят неожиданные граничные случаи

### Конфигурация property-based тестов

Для ESP32-S3 порта используется библиотека **Unity** с расширением для property-based тестирования.

Каждый property-based тест:
- Выполняется минимум **100 итераций** с различными входными данными
- Помечается комментарием с ссылкой на свойство из документа проектирования
- Использует генераторы случайных данных для создания тестовых входов

Формат тега:
```c
// Feature: esp32s3-port, Property 1: Корректность переключения контекста процессов
TEST_CASE("Context switch preserves process state", "[esp32s3][property1]")
{
    for (int i = 0; i < 100; i++) {
        // Генерация случайных процессов
        struct p_tab *p1 = generate_random_process();
        struct p_tab *p2 = generate_random_process();
        
        // Сохранение состояния P1
        uint32_t p1_state[64];
        save_process_state(p1, p1_state);
        
        // Переключение P1 -> P2 -> P1
        switch_context(p1, p2);
        switch_context(p2, p1);
        
        // Проверка, что состояние P1 восстановлено
        TEST_ASSERT(verify_process_state(p1, p1_state));
    }
}
```

### Категории тестов

#### 1. Тесты инициализации (Unit-тесты)

- Проверка загрузки ядра
- Инициализация процессора и MMU
- Обнаружение и инициализация PSRAM
- Инициализация WiFi стека
- Инициализация файловой системы

#### 2. Тесты управления памятью (Property-based)

- **Свойство 2**: Размещение процессов в PSRAM
- **Свойство 5**: Динамическое выделение памяти
- **Свойство 6**: Подкачка при нехватке памяти
- **Свойство 7**: Предотвращение фрагментации памяти
- **Свойство 24**: Защита памяти ядра

#### 3. Тесты WiFi и сети (Property-based + Unit)

- **Свойство 3**: Подключение к WiFi сети (Property)
- **Свойство 4**: Автоматическое переподключение (Property)
- **Свойство 12**: DNS резолвинг (Property)
- **Свойство 13**: Множественные сетевые соединения (Property)
- Сканирование WiFi сетей (Unit)
- Режим Access Point (Unit)

#### 4. Тесты файловой системы (Property-based + Unit)

- **Свойство 8**: Монтирование SD карты (Property)
- **Свойство 9**: Wear leveling (Property)
- **Свойство 26**: Права доступа к файлам (Property)
- Чтение/запись файлов (Unit)
- Создание/удаление директорий (Unit)

#### 5. Тесты многозадачности (Property-based)

- **Свойство 1**: Переключение контекста (Property)
- **Свойство 14**: Вытесняющая многозадачность (Property)
- **Свойство 15**: Планировщик с приоритетами (Property)
- **Свойство 16**: fork() и exec() (Property)
- **Свойство 17**: Межпроцессное взаимодействие (Property)

#### 6. Тесты совместимости (Property-based)

- **Свойство 18**: Совместимость исполняемых файлов (Property)
- **Свойство 19**: Совместимость приложений (Property)
- **Свойство 20**: Совместимость системных вызовов (Property)

#### 7. Тесты безопасности (Property-based)

- **Свойство 23**: Обработка исключений (Property)
- **Свойство 24**: Защита памяти ядра (Property)
- **Свойство 25**: Сохранение дампа (Property)
- **Свойство 27**: Защита WiFi паролей (Property)

### Тестирование производительности

Хотя требования к производительности не являются свойствами корректности, они важны для оценки качества реализации:

- Время загрузки системы (цель: < 5 секунд)
- Время переключения контекста (цель: < 100 микросекунд)
- Пропускная способность WiFi (цель: > 10 Мбит/с)
- Скорость чтения/записи SD карты (цель: > 1 МБ/с)
- Задержка доступа к PSRAM (измерение)

Эти метрики измеряются отдельно и не блокируют релиз, но используются для оптимизации.
